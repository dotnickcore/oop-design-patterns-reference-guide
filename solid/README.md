# SOLID Principles
SOLID Principles are the five fundamentals for clean code developed by Uncle Bob. It is meant to give developers guidelines on how to write maintable, scalable and easy to understand code.

The Principles Are:
1. Single Responsibility (S): A class should have one and only one reason to change. Meaning it should have a single purpose of responsiblity.
2. Open/Closed (O): Software entities such as functions, classes and modules should be open for extension, but closed for modification. Meaning you should add new functionality without altering existing code.
3. Liskov Substitution (L): Objects of a superclass should be replaceable with objects of a subclass without breaking its correctness. Meaning you should remove false assumptions about an entity.
4. Interface Segregation (I): No client should be forced to depend on unnecessary functionalities that a piece of software doesn't need.
5. Dependency Inversion (D): High level modules should not depend on low level modules.
